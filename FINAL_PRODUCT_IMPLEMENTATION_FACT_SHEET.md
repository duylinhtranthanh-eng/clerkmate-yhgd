## 6. Tech stack

**IMPLEMENTED.** React 19.2 + TypeScript 5.9 (strict, `verbatimModuleSyntax`, `noUnusedLocals`) +
Vite 7. **Two runtime dependencies: `react` and `react-dom`.** Hand-written hash router, hand-written
IndexedDB wrapper, hand-written service worker generated by an inline Vite plugin, two hand-written
CSS files. No router library, no state library, no CSS framework, no UI kit, no PDF library.

## 7. Backend status

**PARTIAL — none for core use; one optional function for AI mode.**

- Core app: **no backend.** No server, no database, no API, no accounts.
- One Netlify Function (`netlify/functions/ai-structure-note.mjs`) exists solely to keep an AI
  provider key off the browser. It is contacted only in AI mode, which is off by default.
- GitHub Pages serves static files only and cannot run it, so a Pages deployment has no backend at
  all and reports AI as unconfigured.

## 8. AI runtime status

**PARTIAL — implemented, validated, and never yet run against a real model.**

No provider key is configured on any deployment, so the endpoint answers `{"configured": false}`
and the AI option cannot be selected. It becomes IMPLEMENTED only after a real provider request
succeeds on a deployed build. **Do not describe it as working.**

What *is* verified: request shaping, response validation, the two guards, consent gating, the
fallback for every failure mode, and that no key reaches the bundle.

## 10. Exactly what is sent to the AI

**Two keys, nothing else** — verified by capturing the outgoing POST body in the browser:

1. `note` — the quick-note text the learner typed, capped at 6,000 characters.
2. `fields` — the static field vocabulary (24 targets: key, Vietnamese label, one-line description).
   Application metadata; contains no patient data (asserted by `npm test`).

**Not sent:** the case record, any other section, other quick notes, attachments or images, the
genogram, the completeness snapshot, the learner's name, student ID, class or level, the case ID, or
any identifier. The captured body was checked for all of these.

## 11. Offline behaviour

**IMPLEMENTED — verified with the server switched off, from a repository subpath.**

Service worker active and controlling, scope `/<repo>/`, all 9 precached URLs inside the subpath. A
real network request fails while the app opens from cache, renders the case list from IndexedDB, and
the local parser still produces suggestions. AI mode disables itself and labels why. No background
retries.

## 12. Local storage

**IMPLEMENTED.** IndexedDB `clerkmate` v1, three stores: `cases` (keyPath `id`, index `updatedAt`),
`blobs` (attachment bytes and their sanitized derivatives), `meta` (the learner-profile list, the
active profile id, preferences). Autosave on a 450 ms debounce plus
a flush on `pagehide`/`visibilitychange`; no manual save anywhere. `requireExisting` stops a late
flush resurrecting a deleted case. **Not encrypted.** Schema migration merges a stored record onto a
fresh blank one (verified: a record with no `submission` block still opens; an existing one is kept).

**Several learners can share one device.** Each profile has an id, each case an `ownerProfileId`, and
the home list shows only the active profile's records. The migration from the single-profile shape is
written so it cannot lose work: it runs once, writes nothing to a case but the owner it never had, and
a case that somehow has no owner is shown to whoever is looking rather than filtered into invisibility.
Verified against a planted copy of the old storage — ids kept, cases adopted, second run a no-op
(`npm run verify:profiles`, 14 checks). This is **separation, not authentication**: anyone holding the
device can switch profiles, and the app says so where profiles are managed.

## 13. PWA

**IMPLEMENTED — verified under a subpath.** `display: standalone`, `start_url` and `scope` both
resolve to `/<repo>/`, three icons resolve inside the subpath and load 200. Installable on iOS

## 14. Quick Capture — typed and spoken

**IMPLEMENTED, verified in the browser (`npm run verify:capture`, 29 checks).**

Two capture modes feeding one pipeline. **Gõ**: a notepad for clinical shorthand. **Nói**:
push-to-talk dictation whose transcript is editable *before* structuring, with the original kept
separately — a recogniser mishears, and the correction must not erase what the machine actually
heard.

Each capture is a **fragment**: `source` (text/voice), `originalText`, the working text,
`transcriptionStatus`, `processingStatus`. The inbox — *Ghi chú trong buổi khám* — lists them newest
first with their source, a status badge (chưa sắp xếp · có đề xuất · đã đưa một phần · đã sắp xếp ·
cần xem lại), and the sections they were filed into. Fragments are never auto-deleted after applying.
Both modes are closed with a stated reason when the case is locked (asserted).

Notes written before fragments existed migrate without loss: id, text and `filedInto` are preserved,
`originalText` starts equal to the text, and a note that had been filed is read as already applied.

## 14b. Gap finder — *Gợi ý khai thác thêm*

**IMPLEMENTED, schema-first.** Reads the empty boxes the learner's level asks for and nothing else:
the eight SOCRATES elements one at a time with a tick against those already answered, ICE element by
element, then the unmet requirements a learner can close **by asking**. Each open field carries a
neutral question ("Cơn đau có lan đi đâu không?").

Bounded by checks, not by intention: nine forbidden words (chẩn đoán, xét nghiệm, điều trị, toa
thuốc, …) are swept out of every row; a Y2 is not prompted about ICE because their level does not ask
for it; and the record is compared before and after to prove the panel only reads. It cannot say what
a patient might have, and is not meant to.

## 15. Local parser

**IMPLEMENTED, deterministic, and the default.** `src/parsing/heuristicStructurer.ts`: diacritic-
insensitive normalisation, clause splitting, regex extraction, negation detection, duplicate
detection against the current record. **Not AI.** **40 target fields**, including **all eight
SOCRATES elements**; dictionaries of 54 conditions, 15 drugs, 9 relations, 19 occupations, 14
red-flag patterns.

Verified: every suggestion carries a snippet **that must occur in the fragment's own text**, every
target has an applier, origin stamped `local`. The five acceptance scenarios are checks in
`npm test`: typed shorthand reaching five boxes, a transcript yielding negatives and ICE, medication
with an explicit negative allergy, a note about a knee producing **no** claim about allergy, smoking,
fever or red flags, and a second severity value raised as a conflict rather than an overwrite.

**Negation.** `không · ko · k · chưa · phủ nhận · chưa ghi nhận · không có` are read as negatives.
Silence is not: a note that never mentions allergy produces nothing about allergy. An explicit
"không dị ứng thuốc" sets the form's *đã hỏi, không ghi nhận* flag — it used to file an allergy entry
named "Chưa ghi nhận", which a reader of the printed record would have taken for a real allergy.

Does **not** touch: examination systems, investigations, diagnosis, differential, clinical reasoning,
management, prescription, referral, prevention, follow-up, reflection, genogram layout, or any risk
factor. Asserted by a check that sweeps the whole target catalogue.

## 16. AI parser

**PARTIAL** — see §8. Scope, guards and behaviour:

- Same `NoteStructurer` interface, same `StructuringSuggestion` shape, same `apply.ts` appliers,
  same review sheet. **The learner still ticks each item and presses “Đưa N mục vào bệnh án”.**
- **24 allowed targets**, filtered twice (proxy against the list it was sent; browser against its
  own catalogue). Verified: `diagnosis.primary` is discarded, as is any unknown target.
- **Every suggestion must quote the note.** The browser checks the quoted span actually occurs in
  the note. Verified: a fabricated red flag sourced to a sentence not in the note is discarded, and
  a suggestion with no quote at all is discarded.
- A value the payload builder cannot map is discarded rather than guessed (verified for an
  unparseable blood pressure and an unparseable age).
- Confidence 0–1 maps to the three UI tiers; low-confidence items are **not pre-ticked**.
- **No AI target exists for** diagnosis, differentials, reasoning, management, prescriptions,
  investigations, examination systems, risk factors or scales — asserted by `npm test`.
- **Limit stated plainly:** the guards check provenance, not clinical judgement. A model that
  correctly quotes “Không dị ứng thuốc” and proposes an allergy passes both guards. That case was
  tested: it arrived low-confidence, unticked, with the contradicting quote visible. The human
  review step is what catches this class of error.

## 17. Structured record

**IMPLEMENTED — 18 sections** in 8 groups, each badged live by the completeness engine.
History (HPI, 8 SOCRATES fields, red flags as 6 groups / 31 items in two independent lists, ICE,
systems review) · past/personal history with one-tap “asked, nothing there” · lifestyle (8 fields) ·
family history · Family Medicine assessment (7 family types, 10 life-cycle stages, Family APGAR with
interpretation, SCREEM 6 domains × resources/pathology, home environment, continuity) · examination ·
investigations · attachments · risk review · diagnosis · management · medications · prevention
(10 screening + 7 vaccination items) · SOAP follow-up · learner reflection.

## 18. Completeness

**IMPLEMENTED.** Pure function; never writes to the record. 66 requirement predicates; weighted
percentage (mandatory 3 / recommended 2 / optional 1). Verified by `npm test` and in the browser:

- a blank case is never 100% and satisfies 0 mandatory items at every level;
- the percentage equals the documented weighted formula, and tier totals equal the item list;
- **11 requirements are conditional** — a non-applicable one leaves the denominator rather than
  counting as a failure, so totals are **per case, not per level**;
- editing raises the percentage immediately;
- every missing item has a section rollup, and clicking one navigates to that section (verified).

**Privacy blockers are separate from the score, by design, but not from submission eligibility.**
Attachment redaction is a completeness requirement only from Y5 up *and* an independent submit
blocker; the gate raises both (verified).

## 19. Learner levels

**IMPLEMENTED — 4 levels, cumulative, verified by `npm test`.**

| Level | Requirements | Mandatory | Recommended | Advanced |
|---|---|---|---|---|
| Y2 — Tiền lâm sàng | 17 | 8 | 5 | 4 |
| Y5 — Lâm sàng YHGĐ | 41 | 22 | 14 | 5 |
| Y6 — Thực hành tổng hợp | 60 | 34 | 21 | 5 |
| SDH — Sau đại học | 66 | 54 | 9 | 3 |

**Revised 11 September on the department's instruction.** Family APGAR and SCREEM are required
**from Y2** — they are what makes this a family record rather than a short internal-medicine one;
the genogram **from Y5**; and what SDH adds is **managing a case over time** (treatment goals,
referral, review visits, treatment response, comorbidity control, continuity), not more boxes. Each
assignment is pinned by a check, including one that sweeps all four levels to prove no level drops
what the level below requires. Settings shows each level by what the learner must be able to do
rather than by a count.

Each level covers everything the level below covers (asserted). Gender rule verified (reproductive
history applies to a female patient, not a male one). Age rule verified (cardiovascular risk applies
from 40 and when age is unknown, not at 30). **Previewing another level does not mutate the record
or change its declared level** — asserted in `npm test` and confirmed in the browser. The declared
level is self-declared and unenforceable; the printed record carries a per-page watermark, a level
stamp, the full declared-level history and a warning if the level changed after the case began.

## 20. Genogram

**IMPLEMENTED for three generations.** Deterministic layout; inline SVG, so it prints as vector
(confirmed in the PDF). Square/circle/diamond, X for deceased, double border for the index patient.
Eight hatch patterns assigned by Vietnamese-collated condition name with a printed legend, max 4
bands per person. Patient identity read from the administrative section, never stored twice.
Life-cycle suggestion is rule-based, shows its reasoning and must be accepted.
**NOT IMPLEMENTED:** grandparents, half-siblings, adoption, twins, pregnancy loss, emotional
relationship lines. Stated in the UI.

## 21. Risk review

**IMPLEMENTED — 9 domains, 57 factor definitions** (asserted; ids unique, every factor in a declared
domain). Per-factor “why we ask” line, per-domain bulk yes/no, custom factors, patient-specific
filtering (18 of 57 have applicability predicates). Scaffolding fades by level — Y2 checklist, Y5
recall-then-checklist, Y6/SDH generate — with two deliberate exceptions asserted by `npm test`: the
emergency domain keeps its checklist at **every** level, and the social domain reads from SCREEM.
Seven scales: PHQ-2/9, GAD-2/7, Mini-Cog ship items; **HADS and ISI ship no items** (licensed —
asserted) and take an entered score. Escalation from a positive screen; PHQ-9 item 9 raises a safety
notice. Graded falls assessment (STEADI + Timed Up and Go) with the banding rule printed on screen
and asserted in tests. **Cardiovascular risk is NOT calculated** — inputs, chart used and the
learner's own reading are recorded.

## 22. Clinical examination

**IMPLEMENTED.** Nine vital-sign inputs plus a computed BMI on **WHO Asia-Pacific** cut-offs
(asserted: 155 cm/62 kg → “Béo phì độ I”). Ten organ systems, three states — *Chưa khám /
Bình thường / Bất thường*. One-tap normal writes that system's standard sentence; “Tất cả bình
thường” never overwrites an abnormal system or learner-typed text; *Chưa khám* is never treated as
normal.

## 23. Attachments

**IMPLEMENTED.** Camera or library, multiple files, **6 categories** (including `clinical_photo`),
per-image title/date/category/note, client-side thumbnails, neutral filenames on import. A
photographed result can be attached to the specific result row. **No OCR** — values are typed. All
six blob write paths are lock-guarded (§27).

**Nothing is exported as picked.** Since 11 September an attachment must produce a *derivative*
before it can leave the device, held under `sanitizedBlobKey`: either the redacted image, or a canvas
re-encode made when the learner declares there are no identifiers. Both are re-encodes, so EXIF and
GPS have nowhere to survive — there is no metadata-stripping step to get wrong. An attachment with no
derivative is dropped from the printed images and its list entry says the image was withheld.

**Clinical photos** answer one extra question before the camera opens and again in the viewer: is a
face visible? A declared face **blocks the image** — it cannot be redacted or declared clean, and is
withdrawn from every export path. Blurring is not offered, because a blurred face is still a
photograph of a person that was taken and stored; the app asks for a crop or a retake. An unanswered
face question also blocks, so silence is not a way through.

`src/workflow/privacy.ts` is the single gate and it **fails closed**: a record too old to carry the
field exports nothing. Deleting a case or an image deletes both blobs; a backup carries both.

## 24. Redaction

Draw boxes by dragging; move a box by dragging inside it; resize from a corner handle; several boxes
per image; a “Che dải trên” helper creates a starting box; ①/② step indicator. Verified in a real
mobile-emulated browser with genuine pointer events: a box can be created, moved and a second added.

## 26. Backup / restore

**IMPLEMENTED — verified by the full round trip the task asks for.**

One JSON file holding the profile, every case and every attachment blob as a data URL. Restore
decodes data URLs **in-process** (`atob` → `Uint8Array` → `Blob`), not via `fetch`, so the deployed
Content-Security-Policy cannot block it. Failures are counted and reported rather than swallowed.

Round trip: export → **wipe both IndexedDB stores** → restore.

| Check | Result |
|---|---|
| Backup carries the attachment bytes | ✅ |
| Local data really was wiped first | ✅ 0 cases, 0 blobs |
| Every case comes back | ✅ |
| Case content byte-identical | ✅ full JSON comparison |
| **Attachment image bytes survive** | ✅ SHA-256 identical |
| Redacted state preserved | ✅ |
| Family members / genogram data preserved | ✅ |
| Submission metadata preserved | ✅ |
| Completeness snapshot preserved | ✅ |
| Restore reports what it restored | ✅ “Đã khôi phục N ca, M ảnh.” |

Backward compatible: the format is unchanged, so older backups still restore.

## 27. Submission lock

**IMPLEMENTED — audited across every mutation path.**

Gate → submit → lock → optional reopen. Submitting mints a code (`<studentId>-<YYMMDD>-<nnn>`),
stamps the time, locks the record and downloads a submission bundle. Enforced in **both** write paths
of the editor hook (`update` and `replace`); the two transitions that must write to a locked record —
reopening, and marking a comment read — go through a separately named `replaceWorkflow` so every
bypass is visible at its call site. The six attachment blob paths, which do not go through the editor
at all, are guarded individually.

Verified in the browser on a locked case:

- **17 section editors** and **4 tabs** swept — every enabled input, textarea, chip and small button
  fired (15–63 attempts per section, 400+ in total). The case content fingerprint and all image
  hashes were unchanged after every single one.
- Attachment blob paths: add, sample-insert, redact, delete and privacy-confirm are all disabled,
  and the screen says why.
- **Enforcement survives the UI being forced open**: `disabled` stripped in the DOM and the real
  handlers fired — nothing was written.
- Reopen unlocks, is counted, and clears the submitted stamp so the next send is visibly a
  resubmission; editing works again immediately afterwards.
- Reopen count and the full feedback history are printed in the PDF.

## 28. Teacher grading — **REMOVED 11 September**

**NOT IMPLEMENTED.** The grading interface was deleted on the department's instruction: there is no
`#/cham-bai`, no faculty screen, and no way to import a returned file. The learner's flow ends at the
PDF, which faculty read with the tools they already use. A check asserts the absence: typing the old
route renders nothing and Home offers no grading entry point.

What remains is learner-side and still tested: **eight processing statuses**, five derived from the
record's own content, and the optional lock that marks which version was handed in.

The two review-derived statuses are still in the machine and still keyed **by review id, not by
timestamp** — a bug caught by `npm test` when the feature existed (a reviewer whose clock ran slow
had their decision silently ignored). With no way to receive a review they are now unreachable
through the interface; they were kept rather than removed so that the eight-state answer in the
competition form stays true and the state machine keeps its tests.

## 30. Known limitations

- Requirement levels are the developers' demo rules. **No teaching faculty has reviewed them and
  there has been no study of educational effect.**
- Genogram: three generations only.
- Diagnosis coding: a 20-entry shortlist, not full ICD-10 / ICPC-2.
- No OCR, no speech input, no cloud sync, no cohort dashboard, no search or filtering across cases.
- Cardiovascular risk is not calculated.
- HADS and ISI items are not reproduced; PHQ/GAD/Mini-Cog Vietnamese wording is a working
  translation, not a validated one. MMSE and MoCA are excluded.
- Reviewer workflow has no authentication and no tamper-proofing; the file moves manually.
- One case is one visit plus follow-up entries; there is no patient timeline across cases.
- AI mode needs the internet and a configured provider, and cannot run on GitHub Pages.
- No measured evaluation of time saved or error reduction. Any figure is an estimate.

## 32. Privacy limitations

- IndexedDB is **not encrypted**. Anyone who can open the browser profile can read the records.
- Clearing site data destroys everything; backup is manual.
- **In AI mode the note text leaves the device** and is processed by a third party. ClerkMate makes
  no claim about that provider's retention, training use or jurisdiction. The in-app restriction to
  fictional or de-identified data is a written instruction, **not a technical control** — the app
  cannot tell whether a note is fictional.
- Redaction is destructive for the copy ClerkMate keeps. It cannot affect copies made elsewhere
  (camera roll, cloud photo backup) before the image was imported.
- The reviewer flow is unauthenticated; a submission bundle can be read and edited by anyone holding
  the file.
- No security or privacy review has been carried out by anyone. **No regulatory compliance is
  claimed.**
- Verified: no console output contains quick-note text, case data, learner name or student ID; and
  during a full end-to-end run in core mode the app made **zero** network requests.

## 33. Deployment limitations

- **Live on GitHub Pages** since 11/09: https://duylinhtranthanh-eng.github.io/clerkmate-yhgd/ —
  deployed by Actions on push to `main`, and the served bundle was compared against the local build
  rather than assumed.
- GitHub Pages serves static files only, so **AI mode cannot work there**. It degrades correctly:
  the probe 404s, the app reports “chưa cấu hình” and hides the option. The local parser is the
  default and needs no network.
- Netlify remains the only host that could run the AI proxy, and the only one that sends the
  Content-Security-Policy headers. It was **not** redeployed and is not the submission target.
- Voice dictation needs a network and a browser with a recogniser (Chrome, Safari; not Firefox), and
  the audio goes to that browser's vendor. Typed capture works offline everywhere.
- No licence has been chosen; until one is added the code is not licensed for reuse.
- `netlify-cli` was **removed** from devDependencies on 10/09 — its `sharp` tree carried 5
  high-severity advisories and broke `npm ci` in CI. The project now reports **0 advisories**.
